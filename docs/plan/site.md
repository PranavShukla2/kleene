# The site — second pass

The first pass built the pages. This one is about the difference between a site that is
*finished* and one that is *good*, which is almost entirely made of things nobody names when
they are right and everybody feels when they are wrong.

Ordered by impact per unit of risk. Items marked **⚑** need a decision from Pranav.

---

## What the reference sites actually do

Worth being precise about, because "make it look like an award site" is not a specification.
Five patterns, and what each is *for*:

| Pattern | Seen on | What it buys | Does Kleene need it |
|---|---|---|---|
| The product itself in the hero, touchable | Rive, Figma, Framer | Converts scepticism in one gesture. Nobody believes a screenshot; everybody believes a thing that responds. | **Yes.** This is the single biggest gap. |
| Monospace metadata, precise rules, tight grid | Vercel, Linear | Reads as engineering rather than marketing, which is the claim being made. | Partly done. Extend. |
| Dark-first glass with a lit rim | Raycast, Linear | Depth without decoration. A rim light is one gradient and does more than a shadow. | Yes — cheap. |
| Deliberate page transitions | Arc, Stripe | Makes a multi-page site feel like one application. | Yes. |
| Obsessive small state | all of them | Selection colour, scrollbars, focus rings, empty states, 404. The ones nobody lists. | Yes — this is most of the gap. |

The pattern deliberately **not** copied: scroll-jacking, cursor followers, and full-screen
intro animations. They win awards and lose users, and this is a tool a student opens at
11pm the night before a deadline.

## Track M — identity and the shared shell

Small, and the most visible things on the list.

- [x] **M1.** A favicon. A default globe in the tab is the loudest "unfinished" signal a site
      can send, and it is the one thing visible in *every* tab a recruiter has open.
- [x] **M2.** An Open Graph image, generated by rendering a real page and screenshotting it,
      so it cannot drift from the design. A link pasted into Slack or LinkedIn currently
      previews as nothing.
- [x] **M3.** A 404 page. Unknown paths silently render the overview today, which tells the
      visitor their URL was fine when it was not.
- [x] **M4.** Page transitions. Routes hard-cut; a short crossfade with a few pixels of
      travel is what makes five pages read as one product.
- [x] **M5.** `::selection`, scrollbars, and the focus ring, themed. Every one of these is
      currently the browser default, and the browser default is blue.

## Track N — the hero, made real

The centrepiece. Everything else on this list is polish; this one changes what the page
*claims*.

- [x] **N1.** Let the visitor type a regular expression in the hero and watch the ε-NFA build
      itself. Not a video, not a canned loop — the engine.
- [x] **N2.** Load wasm *after* first paint and upgrade the hero in place, so the
      paint-without-wasm rule (Phase 5 E4) still holds. The canned run is the fallback and
      stays the fallback on a slow connection.
- [x] **N3.** Preset chips (`(a|b)*abb`, `a*b*`, `(ab)*+b`) so the interaction costs one click
      rather than knowing a syntax.

**Tracks M and N closed.**

Two things worth recording.

**The 404 reversed a decision, and inherited its job.** `routeOf` used to send unknown paths
to the overview, reasoning that a stale link should land somewhere explaining what Kleene is
rather than on an apology. The goal was right; the mechanism was not, because a visitor
silently handed the front page cannot tell whether their URL was wrong or the site moved. The
page now does both — it shows the address that failed, then does everything the overview would
have.

**N2 refines Phase 5 E4 rather than breaking it.** The rule is that the overview paints before
WebAssembly arrives, and it still does: the hero renders the canned run first, requests the
engine two animation frames later — one `rAF` fires *before* the paint it was scheduled
against — and upgrades in place. On a slow connection the fallback is a complete experience
rather than a spinner, and a failed fetch is silent, because a front page has nothing useful
to say about WebAssembly and the visitor loses a feature they never saw offered. E4 should be
restated as *"the overview must not block on wasm"*, which is the property that was actually
wanted.

## Track O — the workbench, brought onto the site

The editor is the one page that does not look like the rest, which is the failure a visitor
notices at the exact moment they click the primary call to action.

- [ ] **O1.** ⚑ Decide how far the editor moves. A workbench genuinely needs different
      furniture from a marketing page — the risk here is making the tool worse to look
      prettier.
- [x] **O2.** At minimum: the command bar takes the site's glass, radii and type, and the
      wordmark matches.
- [x] **O3.** A first-run state. An empty canvas with no instruction is the worst moment in
      the product, and it is the first one after the biggest button on the site.

**O2 and O3 done; O1 still needs a decision.** The command bar took the site's type, radii
and wordmark and kept its own density — a workbench earns its screen by fitting more on it, so
the bar stays 44px and its controls stay tight. How much further the editor should move is
still open, and the risk in that direction is making the tool worse in order to look better.

Building O3 surfaced a real bug: the selection survived deleting the states it referred to.
`editor.ts` already carried a comment calling that its one real hazard, and only guarded the
convenient path. Now pruned after every history transition, because undoing an *add* removes a
state and the command alone cannot say so.

## Track Q — the things that make it a product

- [x] **Q1.** A command palette on ⌘K. Every route, example and conversion preset, ranked by a
      tested matcher — and it surfaces the things a nav bar structurally cannot, because
      "Convert `(a|b)*abb`" is not a page.
- [x] **Q2.** `/learn`. The subject rather than the product: four chapters, fifteen
      definitions, and on every one the specific wrong belief that makes it stop working. The
      only page here useful to someone who never opens the tool.
- [ ] **Q3.** ⚑ `/tools/*` landing pages — one page per task ("NFA to DFA", "regex to DFA",
      "minimize a DFA"), each opening straight into the converter. Roadmap §6.1. Worth doing
      once sharing by URL exists, because that is what makes them linkable.
- [ ] **Q4.** Search inside `/learn` and `/docs`, folded into the palette. Waiting on there
      being enough written to be worth searching.

## Track P — the details nobody lists

- [x] **P1.** Loading states for the pages that wait on wasm. They pop in today.
- [ ] **P2.** Empty states with something to do in them, not just a sentence.
- [x] **P3.** A rim light on glass panels — one inset gradient, more depth than a shadow.
- [x] **P4.** Keyboard hints as pills (`⌘K`-style) wherever a shortcut exists. The editor has
      a full shortcut table and the site never mentions it.
- [ ] **P5.** Section rules and monospace section numbers, for the engineering register the
      content is already writing in.

## Not doing

| What | Why |
|---|---|
| Scroll-jacking / pinned scroll sections | Wins awards, loses users. This is a tool opened under time pressure. |
| A custom cursor | Costs a frame budget and an accessibility argument to buy a novelty that wears off in ten seconds. |
| A full-screen intro animation | The fastest way to make a returning user resent a site. |
| 3D / WebGL background | The one heavy thing on a page whose whole claim is that it is light. The aurora does the same job for 0KB. |
